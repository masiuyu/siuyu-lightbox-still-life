# 从设计记录到实际成像

适用于每次图像生成与编辑。先保存简短方向记录，实际运行编译器，再原样使用返回的提示词与参考顺序调用图像工具。单素材任务沿用同一流程；局部编辑可以采用已确定的选择和摄影方案。

## 方向记录

字段示例见 [方向样例](../assets/image-direction.example.json)。该样例演示柔光纸层研究静物；其中的主体、配色、图稿与尺寸关系是一次具体设计，实际任务从本轮输入重新选择。

两个方向候选各有配套成图：[咖啡勺轮廓研究](example-gallery.md#example-02) 与 [咖啡勺表面比较](example-gallery.md#example-06)。图库中的各图方向记录包含其实际成像时的几何与取景细化；复查对应图片时，以该图附带的方向和任务文件为依据。

当前字段样例用现实咖啡勺演示 `contour-study` 与 `surface-study` 两个候选，并以连续乳白透光面和实际被覆笔迹形成柔光箱研究。横竖成图各有独立的方向与原样任务，参见 [柔光箱示例](example-gallery.md#example-09)。

新任务以包内样例了解字段，再从本轮输入编写具体内容。历史方向的读取按 [旧方案的本轮复核](scene-context.md#旧方案的本轮复核) 执行，先保存当前来源范围，再采用用户指定的参考内容。

- `intent`：从当前用户请求确定交付对象、载体和视觉目标。简短生成请求说明采用 Skill 的默认光台研究目标，并概括主体与研究材料的对应、透光层次和完整俯拍构图；用户明确选择的其他目标据实记录。具体造型另写入设计。
- `operation`：`recompose` 使用原始素材组织新画面，也用于主体载体、体块或制作结构的重建；`detail_edit` 用于一个明确编辑目标上已成立构造的局部细化；`concept` 创作用户要求的新概念。
- `inputs`：按调用顺序记录实际图片路径、角色、观察与用途。每条都必须有 `observation`，描述当前文件中的对象与可见差异；它与 `id`、`path`、`use` 从同一次看图建立。确定所指对象与目标呈现后再写 `preserve`：原物采用来源结构与外观，新建模型采用本轮所需辨识特征和用户锁定项。模型的尺寸、造型、材料与配色记录在当前设计中，参考图写明具体采用的视觉或制作关系。
- `inputs[].content_analysis`：内容输入必填。`relationships` 记录来源中的实际关系；`target_scope` 用正面语言列出主体、独立道具、图稿与样片的具体内容、边界及周围应露出的表面；`basis` 逐项说明原始归属或对应的用户要求，制作材料与连接写入后续设计。模型、研究图与造型样片共用部件清单，材料样片对应所选制作材料；完整图面及指定场景各写明范围。先按 [来源关系与呈现范围](object-relations.md) 完成判断，再提取同条输入的 `preserve`。纯风格 `reference` 可按需要填写；纯文字概念按文字任务确定范围。
- `decisions`：按下方契约记录主体依据、场景与选择。
- `design`：`idea`、`pairings`、`composition`、`palette`、`materials`；构图中写明垂直俯拍、主体摆放、画面比例与取景关系。材质保真与配色判断采用 [部位记录和配色依据](material-color.md) 的紧凑格式。
- `photography`：按已确定的视觉目标选择 [摄影预设](../assets/photography-profiles.json) 的 `profile`，覆盖需要调整的字段；也可按 [摄影设定](photography.md) 提供完整自定义方案。镜头、曝光、光照和对焦决定统一在这里维护；编译后检查全部继承字段与本轮构图相容。
- `review_targets`：将完整视觉目标和来源范围分别列为核心项，再记录指定载体、机位与承载面、模型构造和每类物件材料需要呈现的结果。默认方向逐项落实主体与研究材料的对应、透光层次及共同俯拍构图。按 [全场景实物真实性](physical-realism.md) 选择具体可见的位置和关系；图稿、道具、纸层和承托一同覆盖。

重新上传或更换文件后，先实际打开每个新文件再填写当前 `inputs`。方向记录保留完整观察、关系分析与依据；编译出的 `Image N` 采用用途、目标范围、保留项，与 `referenced_image_paths[N-1]` 成组，调用前逐条比对。编译器检查这些字段的完整性与输入绑定；关系判断和目标范围的正确性由实际来源对照确认。复用旧方向时，完成 [旧方案的本轮复核](scene-context.md#旧方案的本轮复核)，补齐当前内容分析和下方内容范围声明，使主体范围、保留项、参考用途、材料与验收目标相互一致后编译。

`pairings.sources` 指向参与构图的内容来源，`pairings.decisions` 指向本关系采用的选中候选 ID，二者都必填。每个选中候选至少由一项关系承接。同一来源含多件物品时，在关系文字中分别说明。新概念中由文字设定的物件可采用空来源列表，并明确它们是本轮创作的内容。

### 选择记录契约

这是可复查的决策摘要，每个文本字段用一两句表达即可。

| 字段 | 内容 |
|---|---|
| `decisions.scope` | 表示搭配选择的开放程度。`open` 在已确定的主体范围内自主设计，至少比较两个不同的 `lens`；`directed` 用于指定搭配或局部编辑，可以记录一个候选。主体、风格或主题已确定而搭配仍开放时，使用 `open`。 |
| `content_scope` | 必填对象，含 `kind` 和 `basis`。`subject_study` 为简短生成请求的默认主体研究范围；`explicit_scene` 用于用户明确要求的场景内容；`explicit_image` 用于用户明确要求保留的完整图面。默认范围的依据写明采用 Skill 的主体研究目标；两种明确范围的依据须摘录当前用户对相应内容的实际要求，并说明适用范围。 |
| `identity_sources` | 提供本轮保留依据的内容输入 ID。以文字设定主体的新概念可为 `[]`。 |
| `subject_basis` | 从原始来源与当前请求确定主体的有限部件清单和载体，再说明该范围内的识别与造型选择；用户明确接受的内容按确认范围使用。 |
| `scene` | `carrier` 写实际呈现方式，`state` 为 `static` 或 `active`，`intent` 写场景选择服务的目的，`support` 写尺度与承载，`activity` 为动作条件列表；静置空间使用 `[]`。 |
| `candidates` | 非空列表，每项有唯一 `id`、`source_relations`，以及 `lens`、`cue`、`basis`、`proposal`、`contribution`、`scene_fit`。`basis` 将所表现的内容逐项对应到主体结构、当前制作材料、独立物件身份或用户明确的内容要求；`proposal` 正面描述要呈现的内容及创作方法，`contribution` 写可见贡献，`scene_fit` 写制作与摆放。通过范围判断的候选再比较设计价值。 |
| `selected` | 最终采用的候选 ID 列表。每项都进入 `design.pairings[].decisions`。 |
| `selection_reason` | 先说明选中方案怎样完成 `intent` 中的整幅画面目标，再说明主体保真、表达价值与场景适配如何支持本轮取舍。 |

`candidates[].source_relations` 为非空且无重复的类别列表，按所表现内容在来源中的关系填写：

| 类别 | 内容依据 |
|---|---|
| `subject_structure` | 主体固有部件、实际装配附件及其造型研究 |
| `subject_surface` | 主体已有表面、纹样和对应的图形研究 |
| `fabrication_material` | 当前选用制作材料的肌理、厚度、颜色或透射比较样片 |
| `independent_object` | 以自身对象身份、用途和搭配贡献成立的工具、器皿等物件 |
| `scene_content` | 用户指定场景中的活动、过程及其图形或造型表达 |
| `complete_image` | 用户指定保留的完整照片或其他完整图面，内容附着于该图面载体 |

同一候选涉及多类内容时全部列出，类别贯穿模型、图稿、样片和道具的转换。`subject_study` 接受前四类；`explicit_image` 另接受 `complete_image`；`explicit_scene` 接受上述类别中符合用户场景范围的内容。编译器检查每个候选的声明，并在选中类别与内容范围相容时才输出任务。选择依据的真实性、类别语义及各段具体文字须由操作者对照原始请求和图片逐项确认；普通生成请求按默认范围记录。

主体状态和情境推导按 [场景状态与情境搭配](scene-context.md) 完成。编译器还验证记录完整性、引用、状态字段相容与选择覆盖；它可检查不同 `lens` 的标识，语义差异和设计价值仍需实际判断。候选的 `cue`、`basis` 和完整备选保存在方向记录中；输出提示词包含选中方案的 `proposal`、`contribution`、`scene_fit` 与当前场景。

照片、图稿与实体之间的转换，先按 [转换时的保留范围](scene-context.md#呈现方式变化时重新建立保留范围) 重新解释来源内容，再填写这些字段。主体载体或制作结构重建采用 `recompose`，搭配已确定时可用 `directed`；`subject_basis` 明确主体固有部件与各层用途，转换区域的保留项、材料和验收目标据此重建。在编译之前完成 [主体与建构审查](scene-context.md#主体与建构审查)，采用经来源对照和方案复查成立的范围。

生命题材成为台面实体时，按 [生命题材的实体呈现](scene-context.md#生命题材的实体呈现) 与 [模型建构](model-construction.md) 建立制作方案。`subject_basis` 写所指对象、实体范围、识别要求及造型转译，`preserve` 记录识别依据；`scene.carrier` 逐件写成品尺寸、造型和工艺，需要比例时由操作者计算；`materials` 用 `designed` 写体量、芯体或覆盖层、连接、细节、材料与颜色转译。摄影负责画面占比，验收按当前模型设计和实物表现进行。

自主搭配与结构、解构表达按 [从主体发展结构](subject-structure.md) 使用现有字段。`idea` 连接主体证据与观看重点；`pairings.relation` 说明辅助图稿、道具或样片怎样对应主体及其载体，`purpose` 说明可见作用。主体在本轮载体中的结构与外观保留项放在来源段，新创作的辅助内容及其表达范围放在关系段，二者一起进入实际调用。

按 [场景状态与情境搭配](scene-context.md) 将来源用途、主体稳定特征与目标状态分别写清。`pairings` 可描述地方、文化或生活情境中的辅助物件，同时包含关联依据、承载方式与画面作用。`composition` 和 `photography.support_and_motion` 共同确定尺度、动静及相互作用，`review_targets` 指向图上需要成立的关系。

## 编译与调用

```bash
python3 <skill-dir>/scripts/build_image_job.py /path/to/direction.json   --output /path/to/image-job.json
```

编译器返回当前内置图像工具可用的 `prompt` 与 `referenced_image_paths`；纯文字概念只返回 `prompt`。摄影预设在编译时展开，明确的覆盖值优先。提示词开头统一写入目标内容与全场景实物摄影要求，随后包含每张输入采用的用途、范围与保留项、主体依据、所选场景与联系、目标部位的材质证据、配色理由与全部有效摄影设置。完整来源观察、关系分类和候选依据保存在方向记录中供审查。记录通过编译后才进入工具调用；按工具规则先查看实际输入。

将编译结果原样作为实际内置图像工具调用参数。若运行环境的工具参数不同，只转换传输字段，保留提示词正文与参考顺序。成像前交叉核对构图、材料、光照与摄影取景：`design.composition` 与 `photography.viewpoint` 共同明确从台面正上方垂直俯拍，主体通过摆放与支撑展示必要结构；同一载体保持一个明确的物理定义，各段描述共同支持该定义。需要修改设计时，先更新方向记录再生成新的任务文件。输出文件采用新版本名。编译失败时补齐或修正记录，再重新运行。

每次修正与首次调用采用同一执行路径，包括材料细化和构造重建。将当前任务文件直接读取为工具参数，可在一次工具编排中完成读取、解析与调用。当前环境提供下列接口时，可按实际文件路径使用：

```javascript
// @exec: {"yield_time_ms": 120000}
const compiled = await tools.exec_command({
  cmd: "cat '/absolute/path/image-job-v2.json'",
  max_output_tokens: 20000
});
if (compiled.exit_code !== 0) throw new Error(compiled.output);
const args = JSON.parse(compiled.output);
const result = await tools.image_gen__imagegen(args);
generatedImage(result);
```

任务文件中的实际提示词、参考顺序与本次传入参数保持一致。交付记录指向真正使用的任务文件；生成后如需修正，回到方向记录并重新编译下一个版本。

生成前先根据原图与任务核对 `content_scope` 和 `content_analysis`：来源中的对象关系是什么，哪些内容成为当前实体、图稿或样片，当前用户要求怎样支持这份范围。逐项核对候选的 `source_relations` 与其实际表现的内容，再连读 `use`、`target_scope`、`preserve`、选中方案、搭配、材料和 `review_targets`，确保它们都采用同一份内容清单和边界。范围依据通过后再审查制作条件。

再把编译结果中的 `Intent`、`Relationships`、`Composition`、`Framing` 和 `Visible photographic result` 连起来读成一幅完整画面。逐项核对目标画幅、完整必要轮廓、连续台面、主次与留白，以及现实器物的功能结构。横竖各自编译，生成后记录实际宽高。默认方向应能具体回答：主体哪项特征对应哪件研究材料，底光穿过什么并在哪里形成层次，以及完整俯拍中如何看清这组关系。答案同时落实到实际物件、材料和摄影字段；用户选择其他目标时核对其对应要求。发现遗漏或冲突时先修改方向并重新编译，形成相容的任务文件后调用。

随后检查实体承托、造型、尺寸、工艺和配色。原物按其保真范围检查，模型按当前设计检查；图稿与样片分别表达其指定研究内容。生成后从原请求与来源重新确认视觉目标及范围，再比较成图。

同时核对所选载体中的场景状态：静置、手部操作或运转具有一致的描述；动态现象的产生条件、来源、路径、作用面和材料反应互相支持。纸面中记录的场景与纸面外的台面空间各自成立。完成这些判断后调用工具，成图复查仍需逐项看图确认。

工具调用完成后保存实际结果、使用的任务文件及简短像素评审。按 [成图判定](physical-realism.md#成图判定) 用具体位置的可见证据记录结论，并完成 [验收记录与状态汇总](physical-realism.md#验收记录与状态汇总) 的校验；生成记录与交付说明采用同一总体状态。工具未披露的型号保持未披露；编译、成像、视觉评估与用户接受分别记录。

## 提示词写法

按“任务、来源、材质证据、主张、关系、构图、配色理由、摄影设定、可见目标”组织，用能在图上验证的语言。位置由分组、轴线、色场和观看顺序决定。材料描述保留证据支持的外观与判断范围。将摄影参数与各部位的光泽、反射形状、清晰范围和运动效果一起写入。

按 [光路字段分工](lighting-optics.md) 将选定的光学作用写成具体画面：哪个光面在产品哪里形成怎样的亮带，哪块暗反射定义曲率，透射、表面补光与接触影分别承担什么作用。保持 `light_response` 的材质目标、`lighting_setup` 的几何关系和 `exposure_intent` 的保留重点一致。

一个有效的关系句包括物件、动作与作用，例如：“两条直线材料沿曲面轮廓的切线成组，圆形部件收住节奏，使原料与成品的几何关系可见。”具体关系由本轮主体决定。

方向记录无需展示给普通成图用户。默认交付图片和必要说明；用户询问方法、需要复用或审查时再提供方向和实际提示词。

同一份方向记录承担参考观察、场景选择、搭配取舍、构图与摄影决策。开放设计的候选比较保持简短；调研用于补足影响选择的事实，布局草图与局部重绘用于解决具体画面问题。风格已明确时，沿用其有效关系并为当前主体重新搭配。
