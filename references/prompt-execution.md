# 自然语言方向到实际图像

AI 负责理解来源、选择画面和检查成图；脚本负责忠实传递已经写好的成像说明。把每个决定写成一幅具体的画面，不必先拆成字段、枚举和候选 ID。

## 方向文件怎么写

`direction.md` 使用普通 Markdown。两段供脚本传递，其余内容是可复查的工作记录。

在 `## 参考图片` 中，每张实际图片单独一行写 `![用途名称](<本地文件路径>)`。路径可相对方向文件，也可用绝对路径；有空格时用尖括号包围。按出现顺序编号为 Image 1、Image 2。每个文件列一次，同一文件的多种用途在正文中分别说明。纯文字创作在这一段说明采用文字方向。

在 `## 成像说明` 中写准备交给图像工具的完整指令。新创作说明画幅、主体与辅助物件、实体制作、材料、光照及必要清晰范围；局部编辑直接说明变化目标、当前主图、参考用途与保持项。每张传入图片都在这里说明用途。正文会原样传给图像工具，只有外侧空白被整理。

其他段落按需要保存来源观察、用户要求、两种方案的简短比较、选择理由、实际材料的不确定性和后续验收位置。它们留在方向文件中供复查。图像中的文字采用用户提供或授权创作的内容，按选定的成字方式、所属空间和成像路径呈现。实物标记随指定表面变化，图中内部显影和数字图面各自遵循本轮采用的影像机制。

英文环境可采用 `## Reference images` 与 `## Image instructions`，编号仍写 Image N。两种语言的说明按同一接口执行。

完整可运行例子：[底光研究](../assets/image-direction.example.md)、[印刷概念](../assets/print-direction.example.md)。它们演示自然语言写法；实际主体、材料和摆放从本轮资料建立。

## 默认编写顺序与平滑控制

写成像说明时先确定一个主视觉目标，按主体层级、构图关系、关键光色与材质、必要细节的顺序展开。把连贯明暗、清楚轮廓、稳定大块面和空间分区写入当前画面，材料细节按自身作用和观看尺度选择。实际写法及摄影、微距和风格条件见 [视觉层级与 Smooth Control](visual-hierarchy-smooth-control.md)。

默认控制在 AI 写方向时生效。采用当前用户明确的风格和表面范围，再保存本张完整成像说明；编译器保持逐字传递。局部修改直接写改变及保持项，实际参数核对这次方向，历史方向按各自版本复读。

先按 [观看任务](restaged-print-world-editorial.md) 确定需要可见的关系、来源角色及结果范围，再沿相同两段接口编译。机位、投影、图形信息、材料与光写成采用的具体结果。照片区需要原样保留时按实际执行路径核对映射；生成式结果采用其真实成图证据。

## 选择与记录

先只看原始来源和用户要求，说明哪些是主体部件，哪些是独立物件，哪些内容属于指定的完整图面。原物材料遵循资料，新建模型的尺寸、工艺与配色是本轮设计。主体范围、图稿研究和模型构造共同使用这一份判断。

开放设计用几句话比较两个不同的观看重点，说明各自怎样改善主体理解、构图和材料表现。确定方案后，把选中的关系写成画面。例如：“纸上的曲线研究沿金属勺柄展开，轮廓折返的位置与实物相邻；两块小钢片分别比较抛光与拉丝，实体和纸层之间留出完整光台。”

用户已确认构图或只要求局部修改时，记录实际接受的范围，再直接细化。需要转换载体、重建体量或承托时，从来源身份重新建立相应结构。

开放设计可以在工作记录中用几句说明：观者任务、主体基本单元、选定操作、保持关系、可变范围和一项困难条件。具体推导见 [形式发展](design-development.md)。成像说明只写已选方案与实际可见结果，编译器继续按原有两段接口传递。

进一步深化方案时，按 [创意判断](creative-judgment.md) 记录采用的关键可见关系、主要代价和一项预期观察。实际提示词直接说明对应形状、光路和位置，判断过程与未来检查保存在其他段落。已有明确决定时沿用相容内容。

复杂任务按 [创作调用](creative-orchestration.md) 核对各决定怎样依赖，按实际需要选读模块。[提示词模式](prompt-patterns.md) 提供主视觉、比较、近景、艺术图面、局部编辑和镜头变化的改写片段；当前对象与已选方案决定采用哪些关系。

可运行的 [开口与透射](../assets/opening-study.example.md)、[竖幅改排](../assets/opening-study-portrait.example.md) 及 [表面比较](../assets/surface-comparison.example.md) 示范了不同观看任务。已有纸面与织物组合按实际面积决定细节可读范围，独立细节任务另行准备与授权。

## 局部编辑采用明确的主图与变化范围

每次选一张完整主图，作为场景、布局及保持内容的依据。其他参考逐张说明只提供的身份、材料、颜色、光或图面；必要时指出使用部位。画幅是输出范围，主体框是定位依据，实际修改范围继续由用户要求决定。参考之间的分工用完整句子说明，沿当前 Image N 顺序传递。

局部编辑直接写目标状态、指定部位、必要融合和保持项。只补充会影响本次结果的环境关系；完整新创作才展开全幅方案。改变材料、照明或姿态时，接触、反射、遮挡与投影可随真实原因一起改变，范围止于这项变化的必要影响。

例如：“编辑 Image 1，将灯罩外表面的细缎面收细，保留灯罩轮廓和开口。Image 2 只提供反射过渡的参考。表面与相邻支杆在原光场中接续，其余物件与机位保持。”若光向是本轮变化，相关表面的亮带与影子也按新光向更新；人物、产品几何和空间位置继续沿主图。

改变表现机制时，重建该机制涉及的完整区域，让轮廓、内部密度、颗粒、锐度与遮挡共同成像。选择保留关系最清楚的主图，再按需要使用独立的身份或材料来源。每次重新列出当前有效的目标和保持项，方向只承载这一版采用的实现。

[BFL 的公开编辑提示词](https://github.com/black-forest-labs/flux-3-image-klein/blob/bfc8889a4497f846416f253a3972a1941ac698b9/src/flux3/pup_prompts_external_vlm.json) 和 [OpenAI 图像提示指南](https://github.com/openai/openai-cookbook/blob/8495326b6f1b7cec94e7f5e393a4045e328a268e/examples/multimodal/image-gen-models-prompting-guide.ipynb) 支持参考分工、局部修改及相容融合的判断。它们各自的提示词格式、模型用语与参数属于对应接口；当前方向继续采用本地自然语言接口，实际可控能力按工具披露与结果核对。

## 编译并核对

有尺寸依据且需要计算取舍时，先按 [可选取景预检](framing-preflight.md) 检查平面范围与细节分配。输入计划和报告属于工作记录；成像说明继续承载最终采用的具体画面。

```bash
python3 <skill-dir>/scripts/lightbox.py compile /path/to/direction.md --output-dir /path/to/new-version
python3 <skill-dir>/scripts/lightbox.py check /path/to/new-version
```

每次选择新的输出目录。编译完成会保存五份文件：可独立复读的 direction.md、图像工具任务 image-job.json、逐字对应的 actual-prompt.txt、实际图片顺序 input-order.md，以及包含方向、提示词和来源指纹的 compilation.json。保存的方向使用已解析的绝对来源路径。

编译只检查本地文件、Image N 对应关系和传递一致性。调用前实际查看每张输入，并连读提示词：主体范围是否有来源依据，参考是否只承担本轮用途，材料与光是否相容，画幅和摆放是否能承载全部必要信息。发现矛盾时回到自然语言方向修改，重新编译新版本。

逐项核对同一对象的内容范围、材料、机位、清晰要求和时间状态。保留标签与新增文字应有相容的整体约束；静态图选一个具体时刻，镜头序列另写起止和主要变化；改变机位、反射或裁区时复查保持项。技术一致性通过后仍需这次语义核对。

连读实际提示词，确认主体层级、构图、关键光色材质与必要细节围绕同一主目标，默认控制与用户明确选择相容。发光、强反射或调色按 [成像处理](image-development.md) 说明具体部位及保持项，改动影响按 [创作调用](creative-orchestration.md) 选择复核范围。自然语言传达外观意图；实际工具字段只采用当前可用接口。

## 实际调用

读取 image-job.json，将提示词与图片顺序原样传入当前图像工具。工具本身的参数是机器接口；其字段转换由执行者适配，方向正文和顺序保持一致。编译命令不会自动生成图片。

当前环境提供以下工具时，可以这样实际调用：

```javascript
// @exec: {"yield_time_ms": 120000}
const saved = await tools.exec_command({
  cmd: "cat '/absolute/path/new-version/image-job.json'",
  max_output_tokens: 20000
});
if (saved.exit_code !== 0) throw new Error(saved.output);
const args = JSON.parse(saved.output);
const result = await tools.image_gen__imagegen(args);
generatedImage(result);
```

先按当前图像工具和 imagegen Skill 的规则查看图片、执行并保存结果。实际调用成功后才记录成像完成；工具未披露的型号保持未披露。记录工具返回文件、项目原生副本、实际宽高和 SHA256，保存真实调用参数。版本目录中的 compilation.json 记录编译时状态，后续执行写到 execution.md，不回写历史编译事实。

已有原生图、真实 imagegen 参数和本轮 review.md 时，可按 [图片证据](image-evidence.md) 使用 `lightbox.py evidence` 建立对应收据，再用 `check-evidence` 复查。原生裁区可按现有坐标索引逐像素核对，实际调用记录作为附件留存。文件一致性、生成记录真实性、视觉效果及用户接受分别判断。

## 评审与修正

先依据原请求和来源重新建立核心要求，再查看全图和 100% 原生细节。把实际看到的关系写进 [评审样例](../assets/review.example.md) 所示的表格，运行 `lightbox.py review` 检查汇总一致性。微小网点、纤维跨界或第二墨层看不清时，保持待确认，下一任务改善相应观察条件。

构图和结构问题从原始身份资料重组；已成立关系中的局部缺陷绑定当前编辑目标。每次先修改 direction.md，再编译、调用、保存原生图和评审。具体效果由新图像证据判断。

## 已有接口的复读

已有 direction.json 可继续通过 build_image_job.py 取得当时的参数。`lightbox.py migrate` 可产生自然语言副本，正文沿用旧编译内容，重新使用前仍需复核来源和当前任务。详见 [接口迁移](interface-migration.md)。
