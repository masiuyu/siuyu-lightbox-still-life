# 自然语言工作方式与接口迁移

正常图像任务从 direction.md 开始，AI 用完整语言说明任务与画面，再由脚本传递提示词和图片顺序。主入口、视觉指南、印刷判断、用户说明和评审都采用这套工作方式。

视觉语言、研究媒介与材料形成通过按需参考参与创作决定。主体材料、图稿媒介、空间光色各按当前任务选择，再写成最终画面。方向的两个传递段、编译命令、图像任务字段和证据接口保持兼容。

## 原先的决定怎样表达

任务意图、重组或局部修改、新概念这些决定直接写成要求。每张来源的观察、用途与保留范围用普通段落说明。候选比较和取舍留在工作记录；最终画面中的主体、纸稿、样片和道具关系直接进入成像说明。

模型与场景用实体尺寸、体块、承托和状态说明；材料与配色用证据、位置及光响应说明；摄影以机位、取景、光和清晰范围说明；印刷按每个表面的内容、分色、基材与墨层说明。执行者实际核对这些关系，脚本保持其传递一致性。

direction.md 只把参考图片与成像说明分开，工作记录可以自由组织。Image N 是图像工具的参考顺序。实际工具任务、指纹和程序报告使用工具自身机器格式，由程序或执行适配生成。

## 现有阶段如何复读

已有 JSON 方向、工具任务、原生图和评审继续保留。

```bash
python3 <skill-dir>/scripts/build_image_job.py /path/to/direction.json --output /path/to/new-job.json
python3 <skill-dir>/scripts/lightbox.py migrate /path/to/direction.json --output /path/to/new-direction.md
python3 <skill-dir>/scripts/lightbox.py compile /path/to/new-direction.md --output-dir /path/to/new-version
```

迁移副本沿用旧方向的实际编译正文，重新编译可核对提示词与图片顺序。它只完成接口转换，当前任务依据、来源判断、设计改进和图像效果继续由实际工作确认。旧字段适配集中在 legacy_image_job.py 与 print_direction.py，已有调用仍可执行。

新方向用自然语言重新梳理即可，长度按画面需要决定。历史大型提示词可用于追溯，当前设计应直接讲清最影响结果的关系。

## 精确处理和工程资料

本地分色与源空间合成也先读自然语言目标，再生成适合现有算法的内部参数卡。尺寸、分色算法、真实透明边界和几何变换需要明确数值与文件；这些是处理程序的机器协议。相关 schema 和工艺库按需读取，并保存实际使用的参数。

配套渲染器工程的已有协议由那个运行时决定。Skill 用自然语言理解任务和规划适配，实际工程变更按明确开发任务执行。实现计划、历史图库和许可证各按自己的用途保留。

## 验证范围

新接口检查图片顺序、路径、正文传递、版本保存和记录汇总；旧案例复读核对实际参数兼容。行为案例检查设计判断是否保留当前请求、来源边界和授权。实际生成、像素评审与用户接受各有独立证据，新版本的成图效果等待相应图像测试。

需要复查实际图片时，可按 [图片证据](image-evidence.md) 建立调用、原生图与评审的对应记录。它使用独立收据，方向两段与原有编译结果保留各自用途；图片证据命令的 Pillow 依赖只作用于该功能。
