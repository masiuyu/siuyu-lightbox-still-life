# 可选的取景计算预检

用于已有平面尺寸或明确设计假设，需要反复比较纸张转角、物件组距、画幅与细节面积的任务。执行者整理计算输入，正常 direction.md 继续用参考图片和成像说明两段。只有需要确定性计算时才使用本工具。

```bash
python3 <skill-dir>/scripts/lightbox.py framing /path/to/framing-plan.json \
  --output /path/to/new-framing-report.json
```

仅需标准库。省略 `--output` 时只输出 JSON；保存时选择新文件，已有报告保留。计算输入的实际文件路径与 SHA256 一起记录。报告是该输入的计算快照，变更计划后重新执行并保存新版本。

## 把当前决定整理成输入

下面采用设计假设，图像像素与实体尺寸分别声明。它展示一次可能发生的取景冲突，具体数字按当前资料或设计选择填写。

```json
{
  "dimension_basis": "design_assumption",
  "basis_note": "实体尺寸与位置是本次规划假设，输出尺寸按预定图像填写。",
  "unit": "mm",
  "output_px": [1672, 941],
  "view_size": [560, 315],
  "margin": 8,
  "items": [
    {"id": "model-footprint", "center": [-180, 0], "size": [90, 190]},
    {"id": "paper", "center": [100, 0], "size": [210, 297], "rotation_deg": 12}
  ],
  "details": [
    {"id": "required-line-width", "width": 0.2}
  ]
}
```

| 输入 | 具体含义 |
|---|---|
| `dimension_basis` | `design_assumption`、`user_supplied` 或 `measured`，记录尺寸依据的声明；程序不核验实测来源。 |
| `basis_note` | 可选，说明哪些来自资料、哪些是设计假设，以及需要进一步确认的范围。 |
| `unit` | `mm`、`cm` 或 `m`；全部实体长度和位置采用同一单位。 |
| `output_px` | 本次图像宽、高的正整数像素。准备阶段填写目标，已有图片可采用其真实尺寸。 |
| `view_size` | 以原点为中心的最小平面覆盖宽、高；实际计算视场向外扩展到输出比例，保持统一比例尺。 |
| `margin` | 可选，各件外轮廓到视场四边的所需余量，默认零。 |
| `items` | 至少一个矩形范围，分别说明唯一名称、中心位置、未旋转宽高与可选转角。 |
| `details` | 可选，说明需要分辨的线宽或结构跨度，单位与其他长度一致。 |

坐标原点在视场中心，x 向右、y 向下，正转角按画面顺时针。物件的位置和尺寸在同一平面中表达；各件转角相对其中心，纸面内容随整张纸转动。矩形用于当前对象的平面包围范围，明显高差、透视、曲面和遮挡继续由 [取景判断](camera-framing.md) 与实际图片处理。

## 读出取舍，再写回方向

`effective_view_size` 是按输出比例扩展后的视场。`items` 为每件列出旋转后的边界、四侧余量、是否位于视场内及是否满足本次余量要求。负余量表示对应边界超出计算视场。

`all_planned_margins_met` 只回答当前平面计划的余量是否满足；输入有效时，计算命令成功退出，余量短缺保留在这个字段中。字段或数值无效则返回错误，报告文件不写出。

`minimum_centered_view_size_for_layout_and_margin` 表示保留当前原点与布局，包含全部矩形及余量所需的最小同宽高比视场。它可以大于或小于现有视场，作为比较选项。若用户已经锁定视场，按允许范围重排物件、调整转角或另选细节任务；最终采用哪项由观看目标决定。

`details` 分别列出现有视场及上述最小视场中的跨度像素。`subpixel_span_in_current_view` 表示该跨度少于一个像素，帮助定位采样分配；一条线能否辨认还受对比、方向、光学与实际成像影响。细节宽度、倍率和图面面积仍是估算输入，实际清晰度要看原生图。

`rounding_tolerance` 仅处理数值运算的舍入误差。维度依据的核验与视觉可读性各自保持未评估状态。报告用于选择取景，不将计划的几何结果写成图片视觉评审。

确定取舍后，只把最终画面中的大小关系、完整边界、留白和关键可见位置写进自然语言成像说明；计算计划与报告留在执行记录。实际工具参数仍由 [方向编译](prompt-execution.md) 生成。生成后按 [图片证据](image-evidence.md) 和原生图核对实际结果。
